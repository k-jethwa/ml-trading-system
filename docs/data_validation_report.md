# V1 Raw Data Validation Report

Generated by `mltrading.data.validate` against the first full ingestion
run (`universe_version = v1-static-2026-08`, 55 tickers, 2015-01-02
through 2026-08-17).

## Result

**50 / 55 tickers fully clean** across every check: no missing trading
days (relative to the observed union calendar), no non-positive prices,
no non-positive volume, no single-day |return| > 50%, no runs of 5+
identical consecutive closes, no duplicate dates.

## Findings

### Missing trading days (5 tickers, low severity)

| Ticker | Missing dates |
|---|---|
| BLK | 2026-07-21, 2026-07-22, 2026-07-31 |
| TJX | 2026-07-21, 2026-07-22 |
| AXP | 2026-07-21 |
| MS | 2026-07-21 |
| SCHW | 2026-07-22 |

All missing dates fall in the most recent month of history (the last ~4
weeks before ingestion), and every other ticker in the universe has full
data on those same dates. This pattern — a handful of unrelated large-cap
names, all missing only the most recent days — points to yfinance
ingestion/backfill lag for very recent bars rather than a real market
event (5 unrelated financial/retail names halting together on the same
two days is not a plausible explanation). Total impact: 8 missing
ticker-days out of 160,710 ticker-days ingested (0.005%).

**Disposition:** accepted as a known limitation for V1. Re-running
ingestion a few days later would likely backfill these. Do not build
any feature or target window that spans exactly these dates without
re-checking freshness first; walk-forward evaluation windows should
avoid using the most recent ~5 trading days as a training boundary
until this is verified stable.

### Everything else: clean

No non-positive prices/volume, no extreme single-day jumps, no frozen
multi-day repeats, no duplicate (ticker, date) rows anywhere in the
universe.
